# 0008. World art (crowd, stage, NPCs, UI, VFX) and parallel Codex production

- Status: accepted
- Date: 2026-10-08
- Builds on: [0006](0006-ai-art-pipeline.md), [0007](0007-art-spec-v2-shippuden-256.md)

## Context

Everything around the fighters is still painted in code: 28 crowd variants (24 x 32 px, idle + cheer), the
tournament stage textures (`src/art/textures.js`), trees, clouds, the sky and a 32 x 48 announcer
(`src/art/crowdPainter.js`). The user wants the authentic Dragon Ball tournament feel: a packed stand of
500+ visibly different anime/manga spectators (many of them recognizable cameos), a hand-made stage, side
characters, UI art and VFX, all generated by Codex with many agents in parallel, while Claude integrates
continuously. Many agents writing to one repository need a protocol that cannot double-assign work.

## Decision

### Crowd

- **Roster: 500+ unique spectators.** Mix of **recognizable cameos** (famous anime/manga characters drawn
  as spectators in their usual outfits) and **original** tournament townsfolk (martial artists, monks,
  families, kids, elders, vendors, animal-folk, punks, rich patrons, robots...). Every cameo entry also has a
  name-free `fallbackLook` for when the generator refuses a name.
- **Copyright:** cameos are fan art of copyrighted characters. Fine for a private fan project; they must be
  removed or replaced (originals only: `cameos: false` build flag, task ENG-020) before any public or
  commercial release unless licensed. Never name a living artist's style.
- **Cell: 64 x 96 px**, transparent, **3 frames per spectator: `idle`, `cheer`, `shocked`**.
  - idle: standing, watching the ring, small personality pose (arms crossed, eating, holding a sign...).
  - cheer: excited (arms up, fist pump, waving a flag, shouting). Arms may rise to y 2.
  - shocked: KO / super moments (jaw drop, hands on head, leaning back, eyes wide).
- **Pivot [32, 94]** (feet center on y 94, 2 px empty below). Front view facing the viewer, camera slightly
  above (~10 degrees). Billboards always face the camera.
- **Height classes** (idle-frame height incl. hair/hat; the packer scales each spectator so its idle frame
  matches): `tiny` 44 (small kids, small creatures) · `short` 58 · `medium` 70 · `tall` 78 · `huge` 84.
  Tall/huge spectators cheer with arms out to the sides, not straight up, so they fit the cell.
- **Scale in the world:** crowd ppu **50** (a medium adult is 1.4 units, a tall one 1.56 = fighter height).
- **Style:** anime/manga pixel art matching the fighters (spec v2 realism for adults, natural proportions
  for kids and creatures), hard pixels, 1 px dark outline, <= 24 colors per spectator, flat magenta raw
  background, no ground shadow, no text (signs held by spectators may show simple shapes, no real words).
- **Raw generation:** one image per spectator: the 3 poses in one row (idle, cheer, shocked), same scale,
  feet on one baseline, on a 1536 x 1024 magenta canvas. Saved as
  `art/crowd/raw/<id>_vNN.png` (highest version wins, rejected -> `art/crowd/raw/_rejected/`).
- **Roster files:** `art/crowd/roster/<group>.json`, one per series or archetype group (parallel writers never
  share a file). Schema:

```json
{
  "group": "dragon-ball",
  "kind": "cameo",
  "series": "Dragon Ball / Dragon Ball Z",
  "spectators": [
    {
      "id": "db-001",
      "name": "Master Roshi",
      "heightClass": "short",
      "look": "elderly martial-arts master: bald, long white beard and mustache, round sunglasses, turtle shell on his back, orange short-sleeve shirt, tan shorts, wooden staff, sandals",
      "fallbackLook": "tiny elderly martial-arts hermit with a long white beard, round dark sunglasses, a green turtle shell on his back, an orange shirt and a wooden walking staff",
      "idle": "leaning on his staff, grinning",
      "cheer": "staff raised high, shouting",
      "shocked": "sunglasses slipping, jaw dropped",
      "tags": ["elder", "martial-artist"]
    }
  ]
}
```

  `id` = `<groupPrefix>-NNN` (lowercase ascii, unique across all groups; it is also the file name).
  Originals use `"kind": "original"`, a `label` instead of `name`/`series`, and no `fallbackLook`.
- **Atlas (packer output):** `public/crowd/atlas.png` + `atlas.json`: 64 cells per row (4096 px wide), each
  spectator = 3 consecutive cells in one row (21 spectators per row), 500 spectators = 24 rows = 2304 px.
  `atlas.json`: `{ "cell": [64, 96], "cols": 64, "ppu": 50, "pivot": [32, 94], "frames": ["idle", "cheer", "shocked"],
  "spectators": [{ "id", "cell", "heightClass", "kind", "tags" }] }`. Missing atlas = procedural crowd.
- **Engine:** seats get unique spectators (reshuffled per match), seat count raised toward ~400, `shocked`
  plays on KOs, ultimates, clashes and big hits; cheer intensity follows excitement.

### Stage set

- Each procedural slot in `src/art/textures.js` (and the tree / cloud / sky painters) can be replaced by
  `public/stage/<slot>.png`. Slot list, sizes, tiling and world coverage: `art/stage/ASSETS.md`. Rules:
  custom art keeps the slot's **world coverage** and tiling (seamless where the slot repeats) at about **4x
  the procedural resolution** (32-64 px per world unit), hard-edged pixel art, World Martial Arts
  Tournament look (white stone ring, Chinese-temple architecture, red/gold banners, lanterns, palms and pines,
  blue sky). Sprites (trees, clouds, parasol) are transparent PNGs; textures are opaque.
- Raw: `art/stage/raw/<slot>_vNN.png` -> approved and fitted to `art/stage/final/<slot>.png` -> packer copies
  to `public/stage/` and writes `public/stage/manifest.json` (slot -> file, size).

### Side characters (NPCs)

- Briefs in `art/npc/`. Cell **128 x 128**, pivot **[64, 124]**, ppu **80**, facing the viewer in 3/4 view.
- Announcer (tournament MC with a microphone; a recognizable DBZ-announcer homage is allowed):
  `idle` 2 frames, `point` 2, `shout` 2, `cower` 2 (hides during big explosions). Two tournament
  monks/officials (`idle` 2, `signal` 2). One food vendor (`idle` 2). Same versioned raw naming,
  `art/npc/<id>/raw/<anim>_vNN.png`; packer -> `public/npc/<id>/sheet.png` + `anims.json`.

### UI and VFX

- UI: `art/ui/` (logo, title key art, menu background, character-select background, results background,
  HUD frame pieces), sizes in `art/ui/README.md`. VFX: `art/vfx/` as specified in `art/SPEC.md` (cells
  unchanged). Both use the versioned names of ADR 0007.

### Parallel production: the claim queue

- **Batches** are the unit of work: 10 spectators per crowd batch (from one roster group), one stage slot,
  one NPC, one UI image, or one VFX effect per batch. `npm run queue -- build` regenerates
  `art/queue/batches.json` from the rosters and briefs (stable ids such as `crowd-db-01`, `stage-grass`,
  `npc-announcer`, `ui-logo`, `vfx-spark`).
- **Claiming is atomic:** `npm run queue -- claim [--type crowd] --agent <name>` creates
  `art/queue/claims/<batch>.json` with an exclusive file create, so two agents can never get the same batch.
  It prints the batch, the prompt file and the exact output file names. Claims older than 3 hours without
  progress become claimable again.
- `npm run queue -- done <batch> --agent <name>` verifies the expected files exist before marking the batch
  `done`; `release` gives a batch back; `status` prints progress and writes `art/queue/STATUS.md`.
- **Workers only write their own batch's files.** Shared files (`art/REVIEW.md`, `TRACKER.md`, manifests,
  rosters) are updated only by the Codex **lead** session, which also packs, builds review contact sheets and
  commits. Workers never commit.
- **Commits:** the Codex lead commits only `art/**` and `public/{crowd,stage,npc,ui,vfx,characters}/**`
  with explicit paths (never `git add -A`). Claude commits only the paths it changed (`src/`, `tools/`,
  `docs/`, root docs). Both retry on `index.lock`.
- **Review at scale:** crowd batches are reviewed as contact sheets (`art/crowd/contact/<batch>.png`, built by
  the packer): the user approves a batch or lists ids to redo. One `REVIEW.md` row per batch.

### Claude's side (runs in parallel)

Engine loaders for every new asset type (crowd atlas, stage overrides, NPC sheets, UI images), the packer's
world modes, the queue tool, tests, and integration fixes reported by Codex in `docs/TASKS.md`.

## Consequences

- New folders: `art/crowd/`, `art/stage/`, `art/npc/`, `art/queue/`; new outputs in `public/crowd|stage|npc/`.
- New tools: `tools/queue.mjs` (`npm run queue`), packer world modes (`npm run sprites crowd|stage|npc`).
- The crowd atlas is ~4096 x 2304 (one texture); fine on desktop GPUs.
- Cameo art is a release blocker for any public build until replaced or licensed (ENG-020).
